# kit-custom-sections — контракт для агентов

Прежде чем править скил, прочитай контракт репозитория: [`../../AGENTS.md`](../../AGENTS.md).

## Safety-контракт скила

1. **Офлайн навсегда.** В `scripts/` нет и не должно появиться ни `urllib`, ни сокетов, ни чтения токенов (`KIT_TOKEN`, `KIT_TOKEN_FILE`, `~/.yandex-kit-skills/kit_api.token`). Флаги подтверждения скила охраняют не запись (записи здесь нет вовсе), а осознанные шаги: `--confirm` — выход из детерминированного режима (`freeform`), `--confirm-slot` — шаблон шапки или подвала всей витрины (`--slot`). Это единственное место, где скил ставит `alias`.
2. **Не заливать чужими руками.** Скил печатает команды `kit-storefront-constructor`, но никогда не запускает их сам и не подставляет `--confirm` (паттерн suggested_fix из kit-store-checkup).
3. **generated не править руками.** Всё в `references/generated/*` собирает внутренний генератор; ручная правка будет перезатёрта и поймана аудитом как TAMPERED. Правки знания — только через генератор.
4. **Паттерны — эталон.** Тела `references/patterns/*/template.hbs|styles.css` побайтно сверяются гейтом G11. Любая правка тройки паттерна — разметки, стилей или `schema.json`, в том числе только `default` или `title` поля, — новая версия паттерна через генератор с абзацем «Переезд с vN» в превью, не правка на месте: по номеру версии G11 узнаёт старую сборку, а по отпечатку тройки — сам паттерн.
5. **Не обещать то, чего нет.** Если паттерна/тега/хелпера нет в справочнике — честный отказ и `gap-report`, а не выдумка. В проде ErrorBoundary рендерит `null`: провал выглядит как пустота без ошибки.
6. **Секция — тройка.** html + css + json_schema. Поле `script` у шаблона в контракте бэка есть, но скил JS не генерирует и не проверяет — это решение скила: JS исполняется только на собственном домене магазина (на `*.yandex.ru` и в превью конструктора — нет), и офлайн его не проверить. Включать генерацию JS — только вместе с гейтами на поле `script` и синхронной правкой `kit-storefront-constructor`, который заливает шаблоны.

## Что где лежит

- `scripts/section.py` — единственная точка входа; `scripts/seclib/` — приватный пакет.
- `references/generated/` — сгенерированное знание DSL (manifest.json с отпечатком).
- `references/patterns/` — каталог паттернов (INDEX.md генерируется).
- `references/manual/` — рукописная механика движка, ловушки и payload контроллеров, которых нет в доке (`controller-payloads.md`). Пункты датируются: это факты кода платформы на дату сверки.
- Эвалы скила живут во внутреннем репозитории, не здесь.
