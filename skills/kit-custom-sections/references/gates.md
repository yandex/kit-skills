# Гейты линтера (G0–G15)

Формат находки: `code / severity / where / what / fix`. Exit 2 при любой ошибке.
Реализация — `scripts/seclib/gates.py`. Реализованы: G1–G8, G11, G12, G16–G19;
заглушки: G9, G10, G13, G14 (G15 — частично, в doctor).

Итерируемое (`#each`/`times`) требует `array`; объект/массив в тексте или внутри строки атрибута — ERROR; объект в атрибуте с документированным скалярным типом — ERROR, с модельным типом (`LinkSource`, `ImageInfoModel`, `Palette`…) — легально, с недокументированным — WARNING; подполя `$ref`-моделей (`cover.url.link`) не судятся; `anyOf`-типы (Palette) не судятся. Тела типов — `references/generated/definitions.json`. Проверен на живых шаблонах без ложных ERROR; ловит и ранее не замеченные дефекты (например, `#each` по объекту) | реализован |
| G17 | **`each` без явного алиаса** (`{{#each x}}` без `as \|m\|`, `<ya-kit-each>` без `as`) — ERROR: поля внутри не читаются, витрина отрисует пустые значения при зелёном линте; все doc-примеры пишут алиас явно | реализован |
| G18 | **`//` и `@import` в css** — ERROR: CSSIsolator платформы вырезает `//` до конца строки без учёта строк и url; один `@font-face` с `url(https://…)` оставляет незакрытую скобку и отравляет каскад всей страницы. Следствие: внешние ресурсы (включая свой шрифт) из css секции невозможны; картинки — через `<img>`/атомы. Экранирование `\2f` — обход санитайзера платформы, запрещено | реализован |
| G19 | **дисциплина заголовков**: больше одного `h1` в шаблоне — ERROR (WARNING при взаимоисключающих ветках if/else, как в официальной карточке товара); дыры в лестнице уровней (h1→h3 без h2) — WARNING. `ya-kit-section-title` рендерит `h3` — заголовки секций каталога выровнены на этот уровень, плитки — `h4`, `h1` только в hero | реализован |

## Что офлайн НЕ проверяется (заявляется, а не обещается)

- Реальный рендер: в проде `ErrorBoundary` рендерит `null` — провал выглядит как пустота.
- Корректность атрибута конкретного атома вне таблиц доки (14+ тегов вообще без таблиц).
- Наличие данных у контроллера на конкретном магазине.
- Визуальная красота.

Проверка живьём — только через `kit-storefront-constructor`: `templates create --confirm` → `content pull` → `section add` → `content push --no-publish --confirm` → просмотр proposal-версии человеком.
