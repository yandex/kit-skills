# kit-custom-sections — контракт для агентов

Прежде чем править скил, прочитай контракт репозитория: [`../../AGENTS.md`](../../AGENTS.md).

## Safety-контракт скила

1. **Офлайн навсегда.** В `scripts/` нет и не должно появиться ни `urllib`, ни сокетов, ни чтения токенов (`KIT_TOKEN`, `KIT_TOKEN_FILE`, `~/.yandex-kit-skills/kit_api.token`). Единственный `--confirm` в скиле охраняет выход из детерминированного режима (`freeform`), а не запись — записи здесь нет вовсе.
2. **Не заливать чужими руками.** Скил печатает команды `kit-storefront-constructor`, но никогда не запускает их сам и не подставляет `--confirm` (паттерн suggested_fix из kit-store-checkup).
3. **generated не править руками.** Всё в `references/generated/*` собирает внутренний генератор; ручная правка будет перезатёрта и поймана аудитом как TAMPERED. Правки знания — только через генератор.
4. **Паттерны — эталон.** Тела `references/patterns/*/template.hbs|styles.css` побайтно сверяются гейтом G11. Косметическая правка паттерна = новая версия паттерна через генератор, не правка на месте.
5. **Не обещать то, чего нет.** Если паттерна/тега/хелпера нет в справочнике — честный отказ и `gap-report`, а не выдумка. В проде ErrorBoundary рендерит `null`: провал выглядит как пустота без ошибки.
6. **Секция — тройка.** html + css + json_schema. Поля `script` в контракте бэка нет ни в одном контуре; JS не генерировать.

## Что где лежит

- `scripts/section.py` — единственная точка входа; `scripts/seclib/` — приватный пакет.
- `references/generated/` — сгенерированное знание DSL (manifest.json с отпечатком).
- `references/patterns/` — каталог паттернов (INDEX.md генерируется).
- `references/manual/` — рукописная механика движка и ловушки.
- Эвалы скила живут во внутреннем репозитории, не здесь.
