# Ловушки (каждый пункт — со статусом достоверности)

## Подтверждённые

- **`hPaddingTouch` в 10/10 официальных примеров** (2026-08-10): html читает `settings.section.hPaddingTouch`, схема объявляет `hPaddingMobile`. Отступ по краям на телефоне молча не работает у всех, кто копировал примеры. Патч каталога `fix-hpadding-touch` правит html; имя ТИПА `SectionHPaddingTouch` в схеме легитимно и остаётся.
- **`or` возвращает boolean** (2026-08-10, код хелпера): `{{or a "fallback"}}` напечатает `true`/`false`, не значение. `isEmpty` тоже возвращает boolean. Текстовый fallback — только тернарным `when`: `{{when (isEmpty x) "запасной" x}}` или `{{when x x "запасной"}}`. `isEmpty` нужен там, где ошибается сам `when`: пустой массив и пустой объект `when` считает истиной, а `0` — ложью (2026-09-24, код хелперов).
- **Строковые хелперы печатают «undefined» и «null»** (2026-09-24, код хелперов): все строковые хелперы, кроме `split`, приводят аргумент через `String()`. Для отсутствующего поля `trim`, `substring`, `replace`, `replaceAll`, `truncate`, `lower`, `upper`, `padStart` и родственные вернут строку «undefined»/«null» (`truncate x 5` → «unde…»), и она уйдёт на витрину. Защита: `{{#if x}}…{{/if}}` или `{{when (isEmpty x) "" (trim x)}}`. `split` для `null`/`undefined` возвращает `[]`.
- **`startsWith`, `includes`, `endsWith` ложно срабатывают на пустом значении** (2026-09-24, код и тест хелпера): `null` превращается в «null», поэтому `endsWith undefined "ed"` → `true`. Перед такой проверкой в условии — `not (isEmpty x)`.
- **`endsWith` без третьего аргумента до 2026-09-10 всегда давал `false`** (дата исправления в коде платформы): в существующих секциях, где это обходили перевёрнутым условием или `unless (endsWith …)`, после исправления рендерится другая ветка. При правке такой секции вернуть условие в прямую форму. Сигнатура: `endsWith x suffix [endPosition]`.
- **`{{!-- --}}` печатается как текст** (2026-08-10): комментариев в DSL нет — удалять.
- **Два инстанса одного шаблона делят id и CSS-скоуп** (2026-08-10, код изолятора).
- **`json.Valid` — единственная серверная проверка** (2026-08-10, код бэка).
- **Таблицы атрибутов в доке неполны**: официальный пример FAQ использует `align` у `ya-kit-section-title`, которого в таблице доки нет (в `tags.md` он добавлен по коду атома с пометкой «(код)»: `default` — выравнивание темы, `left`, `center`). Поэтому неизвестный атрибут — warning, не error. Где код заметно шире доки, справочник дополнен атрибутами по коду движка — в `tags.md` они помечены «(код)».
- **В таблицах доки типографские дефисы** (2026-09-24): 23 имени атрибутов записаны с U+2011 (`is‑disabled`, `on‑change`, `h‑padding‑desktop` и др.), копипаст из доки даёт неработающий атрибут; плюс две кириллические опечатки `is-сollapsable`, `on-сhange`. В справочнике имена нормализованы в ASCII.
- **Зелёный линт без проверки типов пропускал мёртвую секцию** (подтверждено 2026-08-10): объектный `$ref` в скалярной позиции (`titleText: ImageModel` в `text="{{…}}"`) валил секцию целиком — ноль DOM-элементов, ноль ошибок в консоли, CSS при этом впрыснут. Закрыто гейтом G16.
- **Официальный пример custom-snippets сам использует `:global(.drawer …)`**: контент `ya-kit-drawer` рендерится порталом вне скоупа секции — иначе его не стилизовать. Глобальные селекторы делят неймспейс всей витрины: префиксуйте классы контента drawer уникально.
- **`value` вместо `default` в схемах доки** (2026-08-10): примеры running-line и goods-cover содержат нестандартное ключевое слово `value` — форма его игнорирует; при импорте пропатчено на `default`.
- **Повторная привязка одного шаблона на одну страницу дублирует id** (подтверждено 2026-08-10): все инстансы получают одинаковый `id="ya-kit-<templateId>"` — невалидный HTML; стили работают, но ломается всё, что адресуется по id (якоря, getElementById). Для второго экземпляра лучше создать второй шаблон.
- **`//` в css секции отравляет каскад** (подтверждено 2026-08-10): CSSIsolator вырезает `//` до конца строки без учёта строк и url — `url(https://…)` одного `@font-face` оставил незакрытую скобку и обесцветил всю страницу. Никакой внешний ресурс из css секции недоступен: свой шрифт подключить нельзя (только шрифт темы), фоновые картинки — через `<img>`/атомы. Гейт G18.
- **`{{#each}}` без `as |m|` молча даёт пустые поля** (подтверждено 2026-08-10): линт был зелёный, DOM отрисовался без текста и src. Движку обязателен явный алиас — так пишут все doc-примеры. Гейт G17.
- **`--no-chrome` не защищает от подвала** (подтверждено 2026-08-10): сервер молча дописывает `YandexKit.Footer` на страницу, созданную без хрома (шапку — нет, асимметрия). Нативные Header/Footer из секции не перекрасить (портал вне скоупа, `:global(` под запретом). Своя шапка или подвал ставятся только в слот (режим `--slot`, rules.md) и тогда стоят на всех страницах сразу: отдельной шапки для одного лендинга этими скилами не сделать.
- **Вывод `kit.py media upload` — не ImageModel** (подтверждено 2026-08-10, `metadata` — 2026-09-24): команда отдаёт `{id, public_path, file_metadata, …}`, а схема требует `{fileId, filePath}`. Маппинг: `fileId = id`, `filePath = public_path`; если в выводе есть непустой `file_metadata.thumb_hash`, добавить `metadata = {thumbHash: file_metadata.thumb_hash, backgroundColors: file_metadata.background_colors}` (`backgroundColors` — объект `{top, right, bottom, left}`, переносится как есть) — так сохраняет картинку сам кабинет, и витрина строит из этого размытое превью на время загрузки. Без `metadata` картинка грузится с прозрачной заглушкой, а `fit="auto"` не определяет фон. Пустой `thumb_hash` или отсутствие `file_metadata` — `metadata` не передавать. Как есть вывод в answers не вставлять: G8 проверяет required тела ImageModel, а `metadata` без `backgroundColors` G8 отклонит. `thumbUrl` в определении `MediaMetadataModel` — поле рендера, хранить нужно `thumbHash`.
- **Первое медиа товара бывает видео** (2026-09-24, код витрины): `mediaItems` приходят без сортировки по типу, у видео `payload.filePath` пуст, и `ya-kit-image src="{{product.mediaItems.0.payload}}"` показывает заглушку вместо фото. Первое фото — `src="{{first (filterImages product.mediaItems)}}"` (так делает нативный сниппет; паттерны каталога собраны так же), превью любого медиа — `src="{{mediaPreview media}}"`. `ya-kit-media` в карточке сниппета не подставлять: для видео он вставляет плеер, а не превью.
- **Адаптивная вёрстка — CSS-медиазапросами, не ветвлением по `platform`** (2026-09-24, код витрины): на сервере `platform` берётся из User-Agent, в браузере после загрузки пересчитывается по ширине окна (порог 768px), в превью конструктора зафиксирован значением от конструктора. Ветка `{{#if (eql platform "touch")}}` поэтому может смениться после загрузки страницы (что это даёт заметную перерисовку, живьём не проверялось), а превью переключения не покажет. `platform` и `clientType` — для смысловых различий, а не для раскладки.
- **`ya-kit-carousel` сам считает слайды** (2026-09-24, код карусели): прокрутка, навигация и автоплей считают фактические слайды трека, в том числе из `{{#each}}`. Явный `count` приоритетнее: литерал, не совпадающий с длиной массива, ломает прокрутку и цикл автоплея. С циклом внутри `count` не задавать или задавать `count="{{length …}}"`. Гейт G20 (WARNING).
- **Булевы атрибуты атомов пишутся со значением** (2026-09-24, код интерполяции атрибутов): голый `<ya-kit-carousel autoplay>` даёт пустое значение, и автоплей выключен; нужно `autoplay="true"`. То же для `disable-hover-pause` и других флагов. Гейт G3 (WARNING).
- **Автоплей карусели**: `autoplay-delay` по умолчанию 6000 мс (в доке указано 3000 — верить коду), `disable-hover-pause="true"` отключает паузу при наведении. У `ya-kit-media-gallery` атрибут `autoplay` включает автозапуск видео, а не пролистывание слайдов (2026-09-24, код).
- **`ya-kit-video` по умолчанию рисует компактный скин** (2026-09-24, код атома): компактный скин игнорирует `is-skinless` и `hidden-controls` — у фонового видео видны кнопка звука, прогресс и кнопка play на паузе. Фоновое и декоративное видео: `skin-variant="default" is-skinless="true" is-autoplay="true" is-muted="true" is-loop="true"`. Гейт G20 (WARNING).
- **`ya-kit-video` загружает ролик по `fileId` и до загрузки не знает своих размеров** (2026-09-24, код атома): поток запрашивается по `src.fileId`, `filePath` для воспроизведения не нужен — пустой ролик проверять `{{#if m.video.fileId}}`. Пока поток грузится, атом рисует скелетон без `class` и без `aspect-ratio`, а у `aspect-ratio` атома нет 9:16 и 16:9. Вертикальный или широкий кадр держит обёртка с CSS `aspect-ratio` и `overflow: hidden`, а её прямые потомки растягиваются на всю площадь (так сделан паттерн video-reels). Несколько роликов с автозапуском в `ya-kit-video-queue` играют по одному, по очереди, только видимые; `is-loop` внутри очереди игнорируется.
- **`ya-kit-icon` с неизвестным именем рисует пустоту** (2026-09-24, код атома): `name` превращается в имя компонента, неизвестное имя даёт пустоту без ошибки. Составные имена — через дефис по частям: `whats-app`, а не `whatsapp`. Список имён — в `tags.md`; цветов у `color` девять (в доке пять). Гейт G3 (WARNING).
- **`ya-kit-link` сам выбирает вкладку** (2026-09-24, код атома): абсолютный адрес другого домена открывается в новой вкладке с `rel="noopener noreferrer"`; адрес домена витрины, путь и якорь — в той же вкладке; `tel:`, `mailto:`, `sms:`, `tg:`, `whatsapp:` — обычной ссылкой. Адрес без схемы (`site.ru/page`) атом считает путём внутри витрины, поэтому внешний адрес пишется полностью, с `https://`. Атрибут `target` (`_blank` или `_self`, в `tags.md` помечен «(код)») перекрывает выбор. Свой `<a target="_blank">` ради внешних ссылок не нужен.
- **`ya-kit-self-pickup-controller` не читает `quantity`** (2026-09-24, код контроллера): пункты самовывоза считаются для одной штуки товара, атрибут из доки ни на что не влияет. Гейт G3 (WARNING).
- **Feedback-контроллеры вложены друг в друга** (2026-09-24, код контроллеров): `ya-kit-product-feedback-media-list-controller` и `-viewer-controller` работают только внутри `ya-kit-product-feedback-listing-controller`; вне его атом бросает исключение, и в проде секция исчезает. Сам listing берёт отзывы только на странице товара или отзывов и только при включённых отзывах магазина — иначе список тихо пуст. Гейт G20 (ERROR на вложенность).
- **`value-controller` без `initial-value` начинает с `null`** (2026-09-24, код контроллера): сравнение `{{eql controller.value false}}` при этом ложно (`eql` строгий). Начальное значение задавать явно, как в паттерне goods-filters (`initial-value="{{0}}"`).
- **`ya-kit-product-detail-controller` под нативной карточкой удваивает просмотр товара в аналитике** (2026-09-24, уточнено 2026-10-31 по коду контроллера и виджета карточки): каждый экземпляр контроллера при монтировании отправляет событие просмотра товара — ecommerce-событие `detail` в Метрику, цель `view_product_details` и событие в CRM. С 28.10.2026 смена варианта в той же карточке событие повторно не шлёт, но учёт отправленного у каждого экземпляра свой, а нативная карточка отправляет то же самое: секция с этим контроллером под нативной карточкой удваивает просмотры при каждом открытии товара. Разметку товара schema.org Product контроллер с 29.10.2026 тоже выводит сам; под нативной карточкой она совпадает с разметкой карточки (обе строятся из данных страницы), а одинаковые теги разметки менеджер `<head>` витрины оставляет в одном экземпляре — дубля по коду нет (живьём не проверено). `isLoading` у контроллера всегда `false`, ветка со скелетоном не рендерится никогда. Секция, которая дополняет нативную карточку, читает товар из `route.context.productCard.mainVariant` (так сделан паттерн `pdp-product-facts`); контроллер нужен только кастомной карточке, которая нативную заменяет.
- **`$ref ProductVariant` — резервный, но без тела** (код формы и витрины, 2026-10-31): форма рисует выбор варианта товара, но значение у разных клиентов разной формы, общий ключ — только `variantId`. С 29.09.2026 ссылка в общем списке резервных у витрины и формы, витрина её не разворачивает; тела типа нет ни в схеме витрины, ни в `definitions.json`, поэтому поля значения линт не проверяет. Одноимённое определение в собственных `definitions` схемы не объявлять — платформа держит ссылку за собой, тело секции не читается.
- **`ya-kit-accordion` прячет фокус и рисует свою стрелку** (2026-09-24, код атома): заголовок рендерится как `<header role="button" aria-expanded="true|false">` с `outline: none` — с клавиатуры фокус не виден, обводку рисует css секции (`[aria-expanded]:focus-visible`). Встроенная стрелка — svg с `data-icon="true"`: свою иконку ставить, скрыв встроенную. Тело раскрывается анимацией `max-height` 150 мс, высоту считает сам атом — свой `max-height` и обрезку не задавать. `default-expanded` берёт значение выражения целиком: `default-expanded="{{eql index 0}}"`.
- **Заголовок над автополкой повисает над пустотой** (2026-09-24, живые страницы товара): полки `FeaturedProducts` с источником «Похожие» (`relevant`) и «Недавно смотрели» (`last_seen`) скрываются, когда им нечего показать, а отдельный блок-заголовок над ними (баннер с текстом или `section-intro`) остаётся на странице. Заголовок такой полки — только её собственный `titleText`.
- **Текст, запечённый в баннер, нечитаем** (2026-09-24, живые витрины): заголовок или манифест внутри картинки 5:1–10:1 сжимается вместе с ней — на живых витринах абзац в такой полосе выходил около 8px на десктопе и 11–12px на телефоне; его не видят поиск и экранные дикторы, а правка требует новой картинки. Заголовок раздела и манифест — живым текстом (`section-intro`), короткую колонку текста не выключать по ширине (justify даёт «реки»).
- **Изолятор css делит список селекторов по запятым, не глядя на скобки** (2026-09-24, код изолятора): `:where(button, input)`, `:is(…, …)`, `:not(.a, .b)` разрезаются на куски, к каждому приписывается скоуп, и правило ломается без ошибки. Внутри псевдоклассов — один селектор; список — отдельными селекторами через запятую: `.x :where(button), .x :where(input)`. Линт этого не ловит.

## Неподтверждённые (использовать нельзя, проверять живьём)

- **Самозакрывающийся обычный html-тег остаётся открытым**: `/>` движок разворачивает в закрывающий тег только у `ya-kit-*` и `yandex-*` (код), поэтому `<div class="x" />` или `<span />`, по семантике html-парсера, остаются открытыми и забирают соседние узлы себе в дети. Живьём не воспроизводилось. Линт предупреждает (G1 WARNING); писать парные теги.
- «Пустая `json_schema = {}` — поддерживаемый сценарий»: код её пропускает, но «не падает» ≠ «поддерживается». Как продуктовое правило не используется.
- **`<details name="…">` как аккордеон без атома**: в живых шаблонах встречается и работает, но ни `name`, ни `open` в справочнике Mystique нет. Одно имя общее на всю страницу: открытый вопрос в одной секции закрывает открытый в другой, а два инстанса шаблона делят его целиком. Открыть первый вопрос можно только атрибутом `open`, блочный хелпер внутри атрибута запрещён, а по правилам HTML `open` с любым значением, включая `open="false"`, открывает (убирает ли движок такой атрибут, не проверено). В каталоге — `ya-kit-accordion`.
