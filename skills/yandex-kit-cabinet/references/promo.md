# Промо и лояльность — промокоды, скидки, подарки, бейджи, услуги

Endpoint map for the promo/loyalty domain. Auth, base URL, tool flags,
pagination and global conventions live in [`api.md`](api.md).
Mutating = POST/PUT/PATCH/DELETE (all need `--confirm`).

## Какой ресурс брать

Спека помечает ручки одиночных промокодов (`/v1/promocodes`) устаревшими и
отсылает к группам: «Методы устарели — используйте методы раздела «Группы
промокодов»». `describe` печатает у них `(deprecated)` — это указание на
замену, а не запрет: старые ручки отвечают.

- **Новый промокод — всегда группой** (`POST /v1/promocode_groups`). Один общий
  код на всех — `group_type: SINGLE` и один код в `codes`; персональные коды —
  `MULTIPLE`. Копия существующего промокода — тоже новая группа: прочитайте
  исходный и перенесите его условия в тело группы, сверяясь с `describe`.
  Имена полей частично другие: сроки — `valid_from` / `valid_until` вместо
  `promocode_dates.start_date` / `end_date`, а товары, категории и подборки
  привязываются отдельным `objects/add` после создания.
- **Промокод за подписку на рассылку** — тоже новая группа, и именно `SINGLE`
  с одним кодом в `codes`. Окно подписки и секция подписки ссылаются на один
  код, а не на набор персональных, поэтому `MULTIPLE` сюда не подходит.
  Ссылаются они на **id кода, а не группы**. `POST /v1/promocode_groups`
  возвращает только группу, поэтому следом прочитайте её коды:
  `list /v1/promocode_groups/<id группы>/codes` — нужен `id` единственного кода.
  У промокода, созданного раньше через `/v1/promocodes`, его `id` и есть id
  кода. В списке групп тот же промокод виден как группа `SINGLE` со своим,
  другим id — этот id не отдавайте. Куда идёт id кода:
  - **окно подписки** («Редактор сайта → Баннеры и окна») — промокод для него
    выбирает владелец в кабинете, через API окно не настраивается;
  - **секция подписки на странице витрины** — поле `promocodeId` в её
    настройках. Секцию правит `kit-storefront-constructor`: передайте ему id
    кода вместе с самим кодом.
- **Промокод, который уже лежит в `/v1/promocodes`**, читайте и правьте там же
  (`GET`/`PATCH /v1/promocodes/{id}`).
- **«Какие промокоды есть в магазине»** — прочитайте оба списка,
  `/v1/promocode_groups` и `/v1/promocodes` (у второго обязателен
  `-q status=…`). Совпадающий код считайте один раз и не выдавайте один список
  за все промокоды магазина.

## Группы промокодов

Группа — это один набор правил и один или много кодов внутри: `SINGLE` —
обычный промокод, один код на всех; `MULTIPLE` — персональные коды, например
на рассылку. Одиночные промокоды выше и группы ниже — разные ресурсы.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/v1/promocode_groups` | Список групп промокодов (пагинация) |
| POST | `/v1/promocode_groups` | Атомарное создание группы вместе с набором кодов |
| GET | `/v1/promocode_groups/{id}` | Группа промокодов по ID |
| PUT | `/v1/promocode_groups/{id}` | Обновление группы (полная замена, не PATCH) |
| DELETE | `/v1/promocode_groups/{id}` | Удаление группы вместе со всеми её кодами |
| POST | `/v1/promocode_groups/{id}/objects/add` | Привязка товаров/категорий/коллекций (≤500 за запрос) |
| POST | `/v1/promocode_groups/{id}/objects/remove` | Отвязка объектов (≤500 за запрос) |
| GET | `/v1/promocode_groups/{group_id}/codes` | Список кодов в группе (пагинация) |
| POST | `/v1/promocode_groups/{group_id}/codes` | Добавление кода в группу |
| PATCH | `/v1/promocode_groups/{group_id}/codes/{code_id}` | Изменение строкового значения кода |
| DELETE | `/v1/promocode_groups/{group_id}/codes/{code_id}` | Удаление кода из группы |

Ньюансы: обновление группы — это `PUT` (не `PATCH`, как у остальных ресурсов).
`409 Conflict` приходит, когда добавляемый или переименовываемый код уже занят в
другой группе, а также при изменении периода действия, конфликтующем с уже
выданными кодами. `DELETE` группы удаляет все её коды — операция необратима, её
надо показывать пользователю особенно явно.

| POST | `/v1/discounts/{id}/unarchive` | Разархивация скидки |
| POST | `/v1/discounts/{id}/objects/add` | Добавление объектов в скидку |
| POST | `/v1/discounts/{id}/objects/remove` | Удаление объектов из скидки |

### Правила поведения скидок и услуг

- Архивную скидку нельзя обновлять — сначала `unarchive`, потом `PATCH`.
- Привязка категорий или коллекций к скидке **автоматически** переключает её
  режим в `SELECTED_CATEGORIES_COLLECTIONS`; предупреждайте об этом, если
  пользователь ожидал прежнюю область действия.
- У услуги (addon) `binding_mode` нельзя изменить после создания.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/v1/badges` | Получение списка бейджей |
| POST | `/v1/badges` | Создание бейджа |
| GET | `/v1/badges/{badge_id}` | Получение бейджа по ID |
| PATCH | `/v1/badges/{badge_id}` | Обновление бейджа |
| DELETE | `/v1/badges/{badge_id}` | Удаление бейджа |
| GET | `/v1/badges/{badge_id}/variants` | Товары бейджа |
| GET | `/v1/badges/{badge_id}/categories` | Категории бейджа |
| GET | `/v1/badges/{badge_id}/collections` | Коллекции бейджа |
| POST | `/v1/badges/{badge_id}/objects/add` | Добавление объектов в бейдж |
| POST | `/v1/badges/{badge_id}/objects/remove` | Удаление объектов из бейджа |

**Цвет бейджа — собственное поле бейджа, тема витрины его не меняет.**
Шаблонные бейджи яркие — зелёная «Новинка», коралловый «Хит» — и на
спокойной палитре бренда выглядят чужими. Оформляя витрину, перекрасьте их в
палитру бренда: `PATCH /v1/badges/{badge_id}` с `color` в формате `#RRGGBBAA`
(`#2F3A2FFF`). Подтверждение — как у любой правки: бейдж виден на всех
карточках, к которым привязан.
