# Гейты линтера (G0–G22)

Формат находки: `code / severity / where / what / fix`. Exit 2 при любой ошибке.
Реализация — `scripts/seclib/gates.py`. Реализованы: G1–G8, G10 (корни путей), G11, G12, G16–G22;
заглушки: G9, G13, G14 и сверка payload в G10 (G15 — частично, в doctor).

| G7 | санитария html: `<script>/<style>` (вырезаются молча), `iframe/object/embed`, строковые `on*` (не исполняются; свой JS шаблона живёт только в поле `script`, которое скил не генерирует), `javascript:`. Без этого гейта невалидные настройки (например, отсутствующее required-поле или значение вне enum ссылочного типа) отклонял только конструктор при привязке | реализован |

Поля объекта из `{{#with x}}` без `as` не судятся. Фрагмент, который родитель вкладывает внутрь своего контроллера, линтом отдельно даст ложный ERROR — проверять в превью. ## Что офлайн НЕ проверяется (заявляется, а не обещается)

- Реальный рендер: в проде `ErrorBoundary` рендерит `null` — провал выглядит как пустота.
- Корректность атрибута у тегов без таблицы в доке и без ручного слоя по коду (16 тегов, не считая встроенных: в `tags.md` у них статус «только в коде (доки нет)» и прочерк в атрибутах) и значения атрибутов, кроме имени иконки.
- Поле `script` шаблона: скил его не генерирует и не проверяет (G7 только предупреждает, что оно непустое).
- Наличие данных у контроллера на конкретном магазине.
- Визуальная красота.
- Поведение шапки или подвала в слоте: липкость, отступ контента под прозрачной шапкой, место под баннер cookie — только в превью.

Проверка живьём — только через `kit-storefront-constructor`: `templates create --confirm` → `content pull` → `section add` → `content push --no-publish --confirm` → просмотр proposal-версии человеком. Шаблон шапки или подвала — `templates create --chrome-slot header|footer --confirm`, затем перевод слота на шаблон (нативный слот — «Заменить» в конструкторе кабинета, слот на своём шаблоне — `section set --id <id слота> --template-id`) и тот же просмотр.
