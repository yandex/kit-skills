# Механика движка и её следствия (рукописное, 2026-08-10)

- **Неизвестный БЛОЧНЫЙ хелпер** (`{{#foo}}`) — движок бросает исключение, секция падает целиком.
- **Неизвестный тег или контроллер** — движок молча пропускает узел: секция «тихо пустеет», ошибки нет нигде.
- **`<script>` и `<style>` вырезаются молча** (blacklist движка — ровно эти два элемента). CSS живёт только в поле `css`, JS не исполняется вовсе.
- **В проде ErrorBoundary рендерит `null`**: диагностика видна только в превью. Любой провал на проде выглядит как пустое место.
- **`alias` шаблона со значением `YandexKit.Header` / `YandexKit.Footer` подменяет шапку/подвал всей витрины** — поэтому alias всегда пуст.
- **CSS скоупится по ШАБЛОНУ** (`#ya-kit-<templateId>`), не по инстансу: два инстанса одного шаблона на странице делят id и стили. На уникальность `#ya-kit-<id>` опираться нельзя.
- **Живой шаблон править нельзя**: витрина инлайнит актуальную строку шаблона во ВСЕ версии контента — правка мгновенно уезжает всем размещённым секциям, а их settings остаются старыми. Единственный путь: новый шаблон + rebind `template_id`. Откат версии контента шаблон не вернёт.
- **DELETE шаблона наружу не выставлен**; во внутреннем API он существует и каскадно сносит секции с этим `template_id` во всех версиях контента — то есть переписывает историю. Не предлагать удаление как «откат».
- **Единственная серверная валидация схемы** — `json.Valid(json_schema)`. Settings против схемы бэк не проверяет никогда; всё остальное — ответственность этого линтера.

## Правила каталога: ритм и типографика

- **Вертикальный ритм — свойство паттерна, не контейнера.** Платформенный `SectionVPadding` даёт максимум 32px (`single`=16, `double`=32) — для смысловых блоков главной этого мало (норма 80–120px). Воздух даёт ритм-обёртка `kcs-rhythm`, которую эмиттер ставит вокруг КАЖДОГО паттерна: настройки `verticalRhythm`/`verticalRhythmTouch` (spacing-токены, дефолт 500/300 = 40px/24px с каждой стороны → 80px/48px между соседними секциями), задаются в answers. Тела doc-паттернов при этом не трогаются — ритм живёт только на нашей корневой обёртке.
- **Иерархия заголовков каталога.** `h1` — только в hero, с собственной шкалой (52px десктоп / 34px мобильная): платформенный максимум `ya-kit-text` 4xl = 32px иерархии против 24px секционных заголовков не даёт. Заголовки рядовых секций — единый масштаб 24px (`ya-kit-section-title` или `ya-kit-text size="2xl"`); заголовки плиток — `lg` и меньше. Новый паттерн не имеет права заводить третий масштаб заголовка.
- **px против токенов.** Запрет хардкода относится к **цветам** (hex/rgb/hsl перебивают тему). Размерных токенов шрифта в теме нет вовсе, поэтому `font-size` в px — легален и единственный способ типографики; отступы и цвета — только `var(--ys-*)`.
- **Горизонтальные поля по умолчанию** — `hPaddingDesktop: "800"` (64px), `hPaddingMobile: "200"` (16px, как у родной шапки витрины). Дефолт 0/0 даёт страницу, прилипшую к краям; `isFullscreen` контентный контейнер НЕ включает.
