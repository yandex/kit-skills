# Сайт и интеграции — блог, редиректы, вебхуки, гео

Endpoint map for site content and integrations. Auth, base URL, tool flags,
pagination and global conventions live in [`api.md`](api.md).
Mutating = POST/PUT/PATCH/DELETE (all need `--confirm`).

### Как написать статью

Спека называет `content` «Содержимое новости» и ничего не говорит о формате.
На деле витрина разбирает его как **Markdown**: подзаголовки, жирный и курсив,
нумерованные и маркированные списки, ссылки. Статья, написанная сплошными
абзацами, на витрине читается простынёй, и до конца её не дочитывают.

1. **`content` — Markdown.** Подзаголовок `###` через каждые 2–4 абзаца; у
   пунктов — жирная вводная фраза (`**Размер.** …`); шаги — нумерованным
   списком. Абзац — не длиннее 3–4 строк. 1–3 внутренние ссылки на
   `/collections/<slug>` и страницы товаров (адрес берите с витрины), чтобы из
   статьи было куда перейти.
2. **`short_description` — лид в одну-две фразы.** В ленте блога его читают
   раньше заголовка; пустой лид — пустая карточка.
3. **`attachment` — категория или подборка по теме статьи**
   (`{"type": "COLLECTION", "id": "…"}` или `"CATEGORY"`). Тогда статья
   заканчивается блоком «Товары из новости», а не тупиком.
4. **`preview_media` и `desktop_media` — обязательно по смыслу**, хотя схема их
   не требует: без картинки карточка в ленте пустая. Файл загружается
   `kit.py upload`, в `media` идёт его `id`.
5. **`blog_dates.start_date` — время публикации.** Дата в будущем прячет статью
   до этого момента, хотя ответ — `201` и `status: ACTIVE`; `end_date` в прошлом
   снимает её с витрины. Публикуете сейчас — ставьте текущее время. `kit.py
   validate` предупреждает об обоих случаях.

Пример тела `POST /v1/blogs` (ссылки и `id` — свои):

```json
{
  "title": "Как подобрать размер кроссовок",
  "short_description": "Три замера дома и таблица, по которой размер выбирается с первого раза.",
  "content": "**Коротко:** меряйте стопу вечером и прибавляйте 5 мм.\n\n### Как измерить стопу\n\n1. **Лист и стена.** Поставьте пятку к стене, отметьте самый длинный палец.\n2. **Обе ноги.** Берите размер по большей стопе.\n\n### Если размер между двумя\n\nДля бега — больший, для города — меньший. Все модели — в подборке [«Беговые»](/collections/begovye).",
  "blog_dates": {"start_date": "2026-10-01T09:00:00+03:00"},
  "tags": ["Советы"],
  "status": "ACTIVE",
  "preview_media": [{"type": "IMAGE", "display_sequence": 1, "image_id": "<id из kit.py upload>"}],
  "desktop_media": [{"type": "IMAGE", "display_sequence": 1, "image_id": "<id из kit.py upload>"}],
  "attachment": {"type": "COLLECTION", "id": "<id подборки>"}
}
```

## Редиректы

| Метод  | Путь                          | Описание                    |
| ------ | ----------------------------- | --------------------------- |
| GET    | `/v1/redirects`               | Получение списка редиректов |
| POST   | `/v1/redirects`               | Создание редиректа          |
| GET    | `/v1/redirects/{redirect_id}` | Получение редиректа по ID   |
| PATCH  | `/v1/redirects/{redirect_id}` | Обновление редиректа        |
| DELETE | `/v1/redirects/{redirect_id}` | Удаление редиректа          |

`url_from` уникален в пределах магазина: создание дубля вернёт конфликт.
Проверяйте существующие редиректы перед созданием.

## Вебхуки

| Метод  | Путь                                 | Описание                  |
| ------ | ------------------------------------ | ------------------------- |
| GET    | `/v1/webhooks`                       | Получение списка вебхуков |
| POST   | `/v1/webhooks`                       | Создание вебхука          |
| GET    | `/v1/webhooks/{webhook_id}`          | Получение вебхука по ID   |
| PATCH  | `/v1/webhooks/{webhook_id}`          | Обновление вебхука        |
| DELETE | `/v1/webhooks/{webhook_id}`          | Удаление вебхука          |
| POST   | `/v1/webhooks/{webhook_id}/validate` | Валидация вебхука         |

Типы событий (`events` в теле вебхука, enum `WebhookEventTypes`):

- `ORDER_STATUS_CHANGED` — изменился статус заказа;
- `ORDER_PAYMENT_STATUS_CHANGED` — изменился статус оплаты заказа;
- `ORDER_DELIVERY_STATUS_CHANGED` — изменился статус доставки заказа.

## Алерты

Системные уведомления магазина: что требует внимания владельца.

| Метод | Путь                            | Описание                                  |
| ----- | ------------------------------- | ----------------------------------------- |
| GET   | `/v1/alerts`                    | Список алертов (обязателен `-q status=…`) |
| POST  | `/v1/alerts/{alert_id}/resolve` | Пометить алерт решённым                   |

Сортировка: сначала критичные. `resolve` идемпотентен — повторный вызов для уже
закрытого алерта тоже вернёт `204`.
